# Ash 内置 QQ 官方 Bot

使用腾讯官方发布的 `@tencent-connect/qqbot-connector@1.2.0` 和 `@tencent-connect/qqbot-nodejs@1.0.4`，由 Ash 的内部组件管理器按需启动，不需要部署 OpenClaw 或其他桥接项目。

Dashboard 提供两条授权路径：

- 扫码添加：使用官方扫码绑定流程取得 AppID、AppSecret 和扫码者 OpenID。
- 已有 Bot：只填写 AppID，再扫码。Ash 必须核对扫码结果的 AppID；不匹配时不保存、不启用。公开 AppID 本身不是连接凭据。

SDK 的扫码流程在内部进程进行，二维码由本机 `qrcode` 包生成。浏览器只收到会话编号、图片和状态；实际密钥由后端保存到 PostgreSQL。只有扫码者的 C2C 私聊会被转发。群聊、其他用户以及与发送者不一致的回复目标均被丢弃。

内部组件通过回环地址调用 Ash 的现有 `/v1/chat/completions`，使用独立且可停用的凭据。上下文仍然是当前活动会话，不创建独立的 QQ 会话。授权结果不会进入服务端导出备份或本机桌面备份。

启用并绑定 QQ 连接后，助手可使用 `send_qq_notification` 给扫码账号发送文字，无需等待该账号先发消息。停用后工具收起，执行时也会重新检查连接。发送沿用分段与间隔规则，每次最多 12000 字、20 段；平台拒绝、部分失败或超时均返回错误，不自动重发。该工具没有任意收件人参数。

连接详情可设置「附带当前时间」和「等待你说完（秒）」：时间使用北京时间；新连接默认等待 30 秒，每条新消息重新计时，0 表示逐条回复。旧连接沿用已保存的数值。连续消息按顺序合并，整批只在开头附带一次时间和来源，不添加消息编号。回复按换行拆成消息气泡，长行按完整字符分段，气泡之间至少间隔 2 秒；这段等待不含模型生成耗时。

未完成的扫码在离开页面时取消，临时组件最长等待十分钟。若主进程或组件意外退出，不自动重放消息。生产使用默认的单服务副本部署；多个本机 worker 通过文件锁共用一个组件进程。

原生 VPS 部署，在仓库根目录运行 `python3 scripts/setup_bots.py`，会同时准备 QQ 和 iMessage 组件。之后重启 Ash，在 Dashboard 添加或重连；不需要连接环境变量。

单独开发 QQ 组件：

```sh
npm ci --prefix integrations/qq
npm test --prefix integrations/qq
```

扫码与真正的 QQ 消息收发需要使用自己的 QQ 账号完成验证。自动测试只使用模拟授权与消息，不创建真实机器人、不访问用户聊天。
