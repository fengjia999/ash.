# 使用说明

README 之外的细节都在这里：会话、记忆、模型路由、工具、数据与已知问题。

## 会话

会话、消息历史和上下文由网关统一管理。切换、创建、删除走专门的会话流程，前端不直接决定要用哪一段历史。

支持完整历史保留、可选的滚动窗口、手动交接摘要和消息选取。达到配置的上下文上限时会直接报错，不会悄悄丢弃历史。

### 命令

| 命令 | 用途 |
| --- | --- |
| `/compact` | 生成当前会话的交接摘要 |
| `/compact redo` | 在同一消息边界上重新生成摘要 |
| `/message 12` | 选取最近 12 条可见消息用于交接 |
| `/switch [name]` | 保存交接信息并切换到新会话 |
| `/switch 12 [name]` | 生成摘要、选取消息并完成切换 |
| `/status` | 查看当前会话及交接状态 |

## 记忆

| 类型 | 说明 |
| --- | --- |
| 常驻记忆 | 由人维护的稳定信息与偏好。模型提出的新增、修改、删除先进入 Pending，确认后才生效 |
| 流动记忆 | 会话交接后的阶段性摘要，按配置数量滚动归档 |
| 日记与历史资料 | 可检索、可阅读，保留原始内容与来源 |
| 记忆片段 | 后台按轮次以助手第一人称提取并分类 |

检索到的少量记忆片段会作为标注清楚的参考资料，附在当前用户消息开头，不冒充用户的新指令。生成后随该轮消息冻结，续轮不会反复改变同一段上下文。

提取频率、模型设置与对外 MCP 工具见 [MEMORY_RETRIEVAL.md](MEMORY_RETRIEVAL.md)。

## 模型与缓存

同时支持 Anthropic Messages 和 OpenAI 兼容接口，可配置多个供应商。主对话、摘要、Embedding 可以分别指定模型。

对支持 Prompt Cache 的线路，会把稳定提示词、常驻记忆、流动记忆和消息历史放在可复用的边界里，会话交接只重建必要部分。缓存 TTL、命中率和计费由上游决定，不同供应商表现可能不一致。

## 工具

- 内置工具、MCP 服务连接、模型发起的记忆操作、会话搜索
- 网关把记忆相关工具通过 MCP 暴露出去，其他前端可以接入同一套记忆
- 部分客户端支持前端工具调用续轮
- **Heartbeat**（可选）：满足配置条件时检查当前会话，通过允许的工具执行操作或发送通知。工具权限、调用条件和执行记录仍由网关管理

## 界面与本地数据

内置界面以移动端为主：会话、历史、收藏、笔记墙、日记、记忆库、模型配置。支持流式回复、Markdown、历史检索和手动附加上下文。

- 桌面布局、壁纸、图标和部分草稿保存在浏览器本地
- 收藏保留消息快照，不受原消息后续编辑影响
- 笔记文字存服务端，排版位置留在当前浏览器

界面细节见 [DASHBOARD_PHONE.md](DASHBOARD_PHONE.md)。

## 外部聊天入口

支持 iMessage、QQ、飞书 / Lark、微信，见 [integrations/photon/README.md](../integrations/photon/README.md)。实际可用性取决于账号权限、授权状态和接入条件。

## 数据与备份

- 会话、记忆、日记和服务端笔记保存在 PostgreSQL
- 浏览器本地的桌面外观、部分收藏与排版**不在服务端备份里**，需要在浏览器里单独导出
- 服务端备份可选择是否包含聊天历史，恢复前请核对选项，避免覆盖现有数据
- API Key 与平台凭据不要写进 README、提交记录或要分享的备份
- 健康检查端点：`/healthz`

安全与部署注意事项见 [SECURITY.md](../SECURITY.md)。

## 已知问题

- 前端工具续轮在各供应商上的兼容程度不同，模型支持 `tool_use` 不代表整条链路可用
- 关闭浏览器里的流式接收，不一定会让上游停止生成
- 涉及真实平台账号、外部工具和网络访问的功能，请在自己的环境里单独验证
- 部分文档记录的是旧版本行为，以代码和实际配置为准
