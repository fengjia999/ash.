# Dashboard 加载与编辑性能检查

2026-10-17，本地虚构数据测试，未连接线上数据库或真实模型接口。

测试条件：Chromium，390 × 844 视口，CPU 4 倍限速，100 ms 网络延迟，
下载约 1.6 Mbps；500 个会话、80 个长提示词块、20 个预设。
数值来自单次前后对照，受运行环境负载影响，不代表线上延迟保证。

## 本次处理

- Dashboard HTML、CSS、JavaScript 及 GET JSON 响应使用 gzip；
  SSE、写请求、备份导出、二进制资源及 `no-transform` 响应直接透传。
- 带版本的静态文件长期缓存；未带版本的字体缓存一天，其他普通资源保留条件验证。
- Dashboard 和会话 iframe 共享字体、主题等资源的版本，避免重复下载。
- 非当前页专用样式和隐藏装饰图片不再阻塞首次显示；通过 hash 直接打开的页仍优先加载自身样式。
- 收起的历史列表不创建全部会话卡片，展开时使用已取得的数据渲染，不重复请求。
- 提示词块、捕获内容、预设正文以及常驻提示词段落按展开操作填充；编辑器按首次编辑填充。
  正文仍保存在浏览器的数据模型中，折叠不会截断内容。

## 验证和边界

手机和桌面浏览器均验证了展开历史、展开长正文、编辑与保存；没有页面脚本错误。
压缩测试验证解压后内容一致，并逐块验证 SSE 透传。

冷启动仍包含网页、iframe、字体和会话数据的加载，尚未达到秒开。
线上首包、数据库连接池等待、部署平台冷启动及网关链路未实测，部署后需单独测量。

## 会话详情超时的后续处理

- 首次消息页从 50 条降到 20 条；继续向前翻页仍每次最多 50 条，不改变模型实际使用的上下文。
- 管理页面只查询注入提示词的名称等标记，不再从数据库读出随后丢弃的完整正文。
  模型上下文加载仍读取历史注入正文，保持原有内容。
- 增加可见消息 `(conversation_id, id DESC)` 部分索引及注入记录
  `(conversation_id, message_id)` 索引。服务启动初始化数据库时创建，线上查询收益需部署后验证。
- 基础聊天配置与模型发现分开；模型列表慢或不可用时仍可手动填写模型 ID。
  Dashboard 模型发现后端最多等待 7 秒，前端请求最多等待 8 秒；迟到结果不覆盖新输入。
- 外层 15 秒提示改为非全屏的“仍在等待”；消息请求仍有原来的 20 秒截止时间，
  真实失败会显示错误，未通过无限等待掩盖失败。
- 数据库读取超过一秒时记录 `[dashboard-messages]` 阶段耗时，不记录消息正文。

验证：166 项相关测试通过；浏览器模拟 17 秒消息响应与模型列表超时，
确认慢提示后仍能正常打开 20 条消息，手动模型输入可用且不被覆盖。
